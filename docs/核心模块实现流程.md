# 四个核心模块的业务实现流程

> 面向业务说明，覆盖「职责与目标 / 核心数据与关键对象 / 处理步骤 / 模块交互 / 技术栈作用」五个维度。四个模块采用同一结构、同等深度，可直接用于答辩、方案说明或作品集。

---

## 一、画面生成模块

**职责与目标**：把分镜脚本里「深夜写字楼，冷蓝色屏幕光，手指滑落」这类文字描述，转成具备项目画风与角色形象一致性的可视画面；每个分镜一次产出多张候选图，由人工确认一张，作为后续视频生成的首帧。目标是**在可控成本下保证「同一角色在不同镜头长得一样」**，而不是追求单张图的最优效果。

**核心数据与关键对象**：输入侧是 `Shot`（`shot_json` 中的 `action` / `image_prompt` / `composition` / `camera_movement`）、`CharacterAsset`（角色外貌设定与已确认主形象 `primary_media_id`）、`StyleAsset`（项目画风与色板）；输出侧是 `MediaAsset`（`kind=image`、`role=shot_image`、`status=CANDIDATE`）与 `Shot.image_status`（`PENDING → CANDIDATES_READY → CONFIRMED`）。

**处理步骤**：① 提交前置校验——检查该集所有出场角色是否已建档、是否已有确认过的参考图，缺失即阻断并点名角色，避免「先花钱再发现角色设定不全」；② 按项目画幅比例计算输出尺寸，再用供应商能力声明校验尺寸、单镜候选数、参考图张数是否超限；③ 逐镜组装提示词——项目画风 + 该镜出场角色的外貌特征 + 动作 + 构图与运镜 + 画幅，同时把角色主形象作为参考图一并传入，`consistency` 参数随请求留档；④ 调用供应商出 N 张候选，每张独立落库并标记为候选态，该镜状态推进到「候选已就绪」；⑤ 人工在候选区挑选、确认或驳回，确认结果写回 `confirmed_media_id`，驳回的图不再出现在可选列表；⑥ 批处理过程中逐镜检查取消信号，已生成的候选保留、后续镜头不再提交。

**模块交互**：上游消费剧本与分镜模块产出的结构化分镜、角色与画风模块产出的角色卡与参考图；下游为视频生成提供唯一合法首帧；成本模块在该任务创建时按「镜数 × 候选数」预留额度，任务结束时按实际出图张数结算。

**技术栈的具体作用**：SQLAlchemy 维护「素材—分镜—角色」三方关联与状态流转；Provider 抽象把不同生图供应商的尺寸约束、参考图协议、负向提示词差异抹平，换供应商不改业务代码；存储层用独占写入与随机键避免同名覆盖（否则会出现「主角立绘被别的角色顶替」），并提供签名 URL 供供应商读取参考图；异步任务队列承担批量出图的排队、进度推送与协作式取消；Pydantic 模型负责提交前的参数校验与非法枚举归一。

---

## 二、视频生成模块

**职责与目标**：把已确认的静态画面转换为带镜头运动的短视频片段，使成片具备动态表现力。核心目标是**严格把控出片成本**——视频按时长计费，单镜成本是图片的数十倍，因此必须「先确认画面、再生成视频」，且只在人明确点下确认后才消耗额度。

**核心数据与关键对象**：输入侧是 `Shot.confirmed_media_id`（唯一合法首帧）、`shot_json.video_params`（时长、运动强度、运镜）与剧集级参数；输出侧是 `MediaAsset`（`kind=video`、`role=shot_video`、`status=CANDIDATE`）、`Shot.video_media_id` 与 `Shot.video_status`（`PENDING → CANDIDATES_READY → CONFIRMED / SKIPPED`）。

**处理步骤**：① 出片门禁——遍历必做镜头，只要有一个没有确认画面就整体拒绝，并在错误详情里点出具体镜号，防止「跑到一半才发现缺图」；② 逐镜合并参数：镜头级 `video_params` 覆盖剧集级默认值，再按供应商能力做钳制（最短/最长时长、可用分辨率、运动强度区间），避免把不被支持的参数发出去；③ 组装提示词——动作描述 + 画面描述 + 镜头运动 + 运动强度，让模型知道「镜头怎么动」而不只是「画面是什么」；④ 处理首帧引用：本地存储给出的是相对签名地址，外部网关无法访问，因此只把真正的 http(s) 地址当 URL，其余传本地文件路径，由供应商侧上传换取公网地址后再生视频；⑤ 提交供应商任务并等待产物（异步网关需轮询至完成），下载后落库为候选素材，该镜状态推进到「候选已就绪」；⑥ 人工确认后 `video_status=CONFIRMED`，或选择跳过——跳过的镜头在合成时回落到静态图，保证成片不缺镜。

**模块交互**：上游强依赖画面生成模块的确认结果，没有 `confirmed_media_id` 就没有输入；下游向时间线合成提供视频轨，决定每个镜头的实际画面来源；成本模块按生成秒数计费与结算，单条成本可达数百积分，必须回传实际消耗。

**技术栈的具体作用**：httpx 承担长时间轮询与超时控制，供应商返回 5xx 或网络抖动时按可重试标记决定是否重排；Provider 抽象把「同步返回产物」与「提交任务后轮询」两种协议统一成同一个 `generate()` 调用；存储层负责首帧文件的定位与公网地址换取；任务队列通过租约机制避免同一条视频被两个 Worker 重复提交（重复提交等于重复扣费）；SQLAlchemy 维护逐镜状态机，使「确认 / 跳过 / 重试」三种操作互不干扰。

## 三、配音与音频模块

**职责与目标**：为每句台词合成语音，并额外产出一条覆盖整集或若干镜头的氛围音 / 背景音乐轨；台词、音乐、环境音三者分层存储、分层混音，互不覆盖。核心目标是**让音频时间轴与画面严格对齐**，同时在供应商能力受限（不认音色、不认语速）时用工程手段补齐。

**核心数据与关键对象**：输入侧是分镜里的 `dialogue`（文本、角色、情绪）、`CharacterAsset.voice_id` 与 `voice_speed`、`Voice.provider_voice_id`；输出侧是 `MediaAsset`（`kind=audio`、`role=dialogue` 或 `bgm`）与 `AudioTrack`（`kind=dialogue / ambience / bgm`、`line_index`、`start_ms / end_ms`、`stale`）。

**处理步骤**：① 逐镜逐句遍历台词，空台词跳过；② 角色未绑定音色时跳过该句并记录「音色未绑定」原因，不阻断整批（用户可后补绑定再单独重跑）；③ 使用前对齐音色——供应商切换后旧音色 id 会落到默认音色，出现「男声变女声」，因此按当前供应商重映射；④ 组装合成请求：文本 + 音色 + 语速 + 情绪，并在文本前拼接音色指令前缀（供应商不认 `voice` 参数时，靠这段描述控制音色，指令本身不会被念出来）；⑤ 产物落盘前用 FFmpeg 做 `atempo` 变速（只改节奏不改音高），统一转成 WAV 并重写文件头——供应商返回的头部是占位值，不重写会导致播放器显示十小时时长、进度条不可拖；⑥ 写入音轨时按 `line_index` 对位而非按毫秒下标，同一句重跑执行替换而不是追加，避免成片重复念台词或整段音频串位；⑦ 氛围音走独立分支：按作用范围取时间线窗口（整集 / 单镜 / 多镜区间），生成后裁剪到窗口长度并挂到对应起始位置，同位置重新生成即替换旧轨。

**模块交互**：上游消费分镜台词与角色音色绑定；下游为字幕模块提供精确时间轴、为合成模块提供台词与音乐两类音轨；成本模块按千字（台词）与按秒（氛围音）两种口径结算；修改台词会把对应音轨标记为过期，提示重新合成。

**技术栈的具体作用**：FFmpeg 承担变速、裁剪、格式统一与文件头重写，是本模块唯一能补齐供应商能力缺口的手段；Provider 抽象屏蔽 TTS 协议差异（有的用 `input.text_prompt`，有的用 OpenAI 兼容格式）；SQLAlchemy 维护 `line_index` 与 `stale` 标记，保证「哪句过期了」可被精确查询；异步任务队列支持逐句进度与中途取消，已完成的句子不会因为取消而丢失。

## 四、合成导出模块

**职责与目标**：把镜头、音轨、字幕组装成一条可播放的时间线，用 FFmpeg 渲染成可交付的成片，并提供三种交付形态——低码率预览（快速看效果）、正式导出（可交付成片）、素材包（打包原始分镜素材）。核心目标是**让「所见即所得」成立**：前端看到的时间线、校验提示、成片内容三者一致。

**核心数据与关键对象**：核心是 `build_timeline()` 产出的时间线结构，包含视频轨（`shot_id`、`start_ms`、`duration_ms`、`media_id`、`kind=video/image/placeholder`、转场）、台词轨（按镜头基线 + 序号排布）、BGM 轨（绝对起止）、字幕轨（`start_ms` / `end_ms` / 文本）；输出侧是 `exports` 记录（`kind=preview/final`、`status`、`manifest`、`media_id`）与 `entity_versions` 中的时间线快照。

**处理步骤**：① 构建时间线——按镜号顺序排布，处理转场重叠（后一镜起点前移、总时长相应缩短）、音轨基线（每镜音轨以本镜起点为基准）、字幕偏移；支持「只取已就绪镜头」的部分模式，未就绪镜头剔除后后续镜头自动前移，字幕与音轨按新旧基线重映射；② 合成前校验——逐项检查缺画面、缺台词音频、音频已过期、素材比例与项目画幅不符、转场时长超限、BGM 未声明使用权，错误与告警均可定位到具体镜号；③ 组装 FFmpeg 滤镜图——视频轨做缩放补边、克隆补帧、定长裁剪、固定帧率后拼接（有转场则用 `xfade` 交叉淡化）；音频轨做格式统一、按需裁剪、音量与淡入淡出、延时对齐，最后与静音底座 `amix` 混合以保住总时长；字幕与 AIGC 标识用 `drawtext` 烧录；④ 按产物类型选择编码参数——预览用极速预设与高 CRF 限制码率，正式导出用中等预设与高码率、High Profile；⑤ 落盘后写入素材库与导出记录，`manifest` 记录时长、分辨率、镜头数、告警；正式导出额外保存一份时间线快照便于回溯；⑥ 交付——预览在页面内播放，正式成片可下载，素材包按镜头目录打包 ZIP。

**模块交互**：消费前四个模块的全部产物（画面、视频、台词音轨、氛围音、字幕），任何一个缺失或过期都会在这里暴露；成本模块按输出秒数占用配额；安全模块若存在未解决的内容拦截，会直接拒绝导出；修改镜头时长或转场后必须重新校验，否则音画会错位。

**技术栈的具体作用**：FFmpeg 是唯一的重活执行者，负责拼接、转场、混音、字幕、水印与元数据写入；SQLAlchemy 维护时间线快照与导出记录，使「这份成片当时的时间线长什么样」可回溯；Pydantic 承载校验结果的结构化输出（错误码 + 镜号 + 轨类型）；异步任务队列与 SSE 让「几分钟的渲染」有实时进度；存储层的 Range 支持保证成片在浏览器里可以拖动播放，而不是黑屏或进度条失效。

## 附：四个模块的链路关系

```
画面生成 ──确认图──▶ 视频生成 ──视频轨──┐
                                        ├──▶ 合成导出 ──▶ 预览 / 成片 / 素材包
配音与音频 ──台词轨 / BGM 轨───────────┘
     └──时间轴──▶ 字幕 ─────────────────┘
```

四者共同的约束是**成本与人工确认**：每一步生成前都要预估并预留额度，每一步产出都要人确认后才进入下一步；因此模块之间的接口不只是数据传递，还包含状态门禁（没有确认就没有输入）。

# 精简讲稿版（每段约 300 字，适合口头讲述）

## 一、画面生成

画面生成把分镜文字变成画面：一个分镜出几张候选图，人工挑一张作为视频首帧。核心对象是分镜的动作与画面提示词、角色卡的外貌和已确认主形象、项目画风；产出是候选图素材和分镜的画面状态。

流程四步：先查角色，没建档或没确认参考图就拦住，不让钱白花；再按项目画幅算尺寸、按供应商能力核对张数与参考图上限；然后逐镜拼提示词——画风、角色长相、动作、构图运镜，角色主形象当参考图一起传；最后出图落库，人工确认或驳回，确认的那张写回分镜。

上游吃剧本和角色资产，下游给视频供首帧，成本按镜数乘候选数预留。技术上 Provider 抽象抹平了各供应商在尺寸、参考图协议上的差异，存储层独占写入防止同名覆盖，异步队列负责批量出图和随时喊停。

## 二、视频生成

视频生成把静态图变成会动的片段，成本是图片的几十倍，所以第一原则是图没确认绝不提交。核心是已确认的画面、镜头与剧集级参数（时长、运动强度、运镜），产出候选视频与视频状态。

流程四步：门禁，遍历必做镜头，有一个没确认画面就整体拒绝并点名；合并参数，镜头级覆盖默认值，再按供应商能力钳住时长和分辨率；拼提示词，动作、画面、镜头怎么动、运动强度；处理首帧，本地存的是相对地址、外部网关访问不到，所以只把 http 地址当 URL，其余传本地文件让供应商换公网地址，再轮询拿到成片。

下游给时间线提供视频轨，跳过的镜头回落静态图。技术上两个关键点：租约防止同一条视频被两个 Worker 重复提交（重复提交就是重复扣钱）；协议统一把「同步返回」和「提交后轮询」封在同一个接口后面。

## 三、配音与音频

配音解决两件事：每句台词有人声，整集还有一层氛围音；三层音轨分开存、分开混。核心是台词文本和角色音色，产出带台词序号和过期标记的音轨。

流程：逐镜逐句取台词，空台词跳过；角色没绑音色就跳过这句并记下原因；合成前对齐音色，换供应商后旧音色会落回默认值、男声变女声；请求带文本、音色、语速、情绪，前面加一句音色指令——供应商不认音色参数时靠它控音色；拿到音频先变速（只改节奏不改音高），转 WAV 并重写文件头，否则播放器时长错乱、进度条拖不动；写音轨按台词序号对位，同一句重跑是替换不是追加，否则会重复念词或整段串位。氛围音单独走：按镜头区间取窗口，生成后裁到窗口长度。

下游给字幕提供时间轴、给合成提供音轨。技术上最关键的是 FFmpeg 变速与重写头部。

## 四、合成导出

合成导出是收口：镜头、音轨、字幕拼成时间线，用 FFmpeg 渲成片，出预览、正式成片、素材包三种形态。核心是四条轨：视频（起点、时长、素材、转场）、台词（镜头基线加序号）、音乐（绝对起止）、字幕（每条起止）。

流程五步：建时间线，处理转场重叠，支持只取已就绪镜头并重映射字幕音轨；校验，缺画面、缺音频、音频过期、比例不符、转场超限、音乐没声明权利，每条能定位到镜号；组装滤镜图：视频缩放补边、定长、统一帧率再拼，有转场就交叉淡化；音频统一格式、裁剪、调音量、淡入淡出后与静音底混合；字幕和水印烧上去；选编码，预览压码率、导出用高码率；落库记清单，导出再存时间线快照。

它吃前面所有模块的产物，任何缺失都在这里暴露。技术上 FFmpeg 干所有重活，Range 支持保证成片能在浏览器里拖动。
