# hoyo漫剧 · 项目说明

> 一句话：给个人创作者的 **AI 漫剧生产线** —— 输入一段故事，经过 **8 个智能体 + 6 个人工确认门控**，产出可直接发布的竖屏成片（MP4）与可交付素材包（剧本 / 角色卡 / 图片 / 视频 / 音频 / 字幕 / 权利声明）。

- 代码：`backend/`（FastAPI）、`frontend/`（Vue 3）
- 接口契约：`docs/API.md`（前后端唯一事实来源）
- 实现细节：`docs/实现说明.md`
- 迭代计划：`docs/PRD-差距分析与升级计划.md`

---

## 1. 项目背景

### 1.1 要解决的问题

竖屏漫剧（有声漫画 / 微短剧）需求量大，但传统流程要编剧、分镜、美术、配音、剪辑五拨人协作，**个人做一集要数周**，且角色形象难保持一致。

单点 AI 工具只能解决「生成一张图 / 一段配音」，落到实际生产会卡在四个地方：

| 痛点 | 具体表现 |
| --- | --- |
| **不可控** | 一次生成一整套，某一段不满意就整条重来，没法只改第 4 镜 |
| **不可信** | 模型直接产出 JSON，字段缺失/枚举写歪就整条流水线崩掉，用户看不懂错误 |
| **不可持续** | 角色每张图都长得不一样，跨镜头无法连戏 |
| **不可交付** | 没有成本台账、没有失败重试、没有版权与 AIGC 标识材料，成片不敢发 |

### 1.2 本项目的回答

把「抽卡」变成「可控生产」，靠四件事：

1. **分段确认**：21 个工作流节点、6 个人工门控（剧本 / 角色与画风 / 分镜画面 / 视频成本 / 视频片段 / 导出），每段都能改、能驳、能只重做局部；门控通过 LangGraph `interrupt()` 暂停，确认后从 checkpoint 续跑，**不重跑已完成节点**。
2. **一致性资产**：角色卡（外观 / 服饰 / 性格 / 说话风格 / 禁用变化）+ 主参考图作为图像生成的参考输入，跨镜头锁定同一个人。
3. **成本可控**：两段式生成（先出静态图确认，再图生视频），每一步先预估再扣费；台账 `RESERVE → SETTLE/RELEASE`，幂等键防连点重复扣费。
4. **可交付**：成片强制带 AIGC 标识；素材包内含 `rights.json`、`manifest.json`（含 sha256）、剧本与字幕；删除/导出/配额调整全程审计。

### 1.3 目标用户与定位

- **目标用户**：个人漫剧作者、1~3 人内容小团队、需要批量出竖屏短内容的运营。
- **产品定位**：本地优先的生产工具 —— 零外部中间件（SQLite + 本地磁盘 + 内嵌 worker + FFmpeg）就能跑完整闭环；供应商可插拔，未配密钥自动回退 Mock，**离线也能全链路验收**。
- **非目标**：内容分发社区、多租户 SaaS（当前单用户 `usr_local`）、专业级剪辑器。

## 2. 一句话闭环

```
故事输入 → ①剧本确认 → ②角色/画风确认 → ③分镜图确认
        → ④视频成本确认 → ⑤视频片段确认 → TTS/字幕/合成 → ⑥导出确认 → 成片 + 素材包
```

对应 21 个节点：

```
initialize → safety_check_input → story_agent → validate_script
  → [gate①] → character_agent → [gate②]
  → shot_agent → image_generation → [gate③]
  → cost_estimate → [gate④] → video_generation → [gate⑤]
  → audio_agent → audio_generation → edit_agent → render_preview
  → [gate⑥] → export → completed
```

## 4. 核心功能详解

### 4.1 故事与剧本生成

**做什么**：用户写一段创意或故事正文 → 生成 `StoryBible`（人物表 / 场景表 / 冲突）+ `BeatSheet`（剧情节拍）+ `ShotScript`（分镜初稿），并可逐版迭代、手工编辑 JSON。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 供应商适配层（DeepSeek / 火山方舟 / OpenAI） | 同一份 `TextRequest` 换供应商不改业务代码 |
| JSON Schema 强约束 + 自动修复一次 | 首次输出不合规时把错误回灌给模型重写一次，两次都失败才报错 |
| Pydantic v2 `Literal` + `field_validator(mode="before")` | 真实模型不会照抄枚举，`normalize_enum()` 把「推镜头」「pan」「仰拍」归一成规范值 |
| 角色名宽容匹配 | 「林晚（女主）」→「林晚」，对不上就丢弃该引用，而不是整条失败 |
| 版本服务 `versions.record()` | 每次生成/手工保存留一条带 `input_digest` 的版本，可对比差异 |
| 单一 Prompt 来源 `build_script_prompt()` | 成本预估与实际调用共用，避免「预估与实扣不符」 |

**接口**：`POST /episodes/{id}/story/generate`、`GET/PUT /episodes/{id}/script`、`POST /story/analyze`

---

### 4.2 角色卡（角色资产库）

**做什么**：剧本生成后**立即**从人物表抓取角色，生成可编辑的角色卡（身份 / 年龄段 / 外貌 / 服饰 / 性格 / 说话风格 / 禁用变化），并为每个角色生成/确认主参考图。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 自动同步 `sync_characters_from_script()` | 剧本一落库就建卡，用户不必先跑工作流 |
| **按剧集隔离**（`character_assets.episode_id`） | 同一项目下多集同名主角（EP02 魔王「陈默」、EP03 刑警「陈默」）各存一张，互不覆盖 |
| 手改保护（`spec_json._user_edited`） | 用户改过的字段再同步不会被覆盖，`force=true` 才整体覆盖 |
| 参考图一致性 | `primary_media_id` + 参考图作为图像请求的 `reference_uris` |
| Alembic 迁移 + `UNIQUE(episode_id, name)` | 约束从「项目内名字唯一」改为「剧集内名字唯一」 |

**接口**：`/projects/{id}/characters`（支持 `episode_id` / `include_all`）、`/characters/{id}`、`/episodes/{id}/characters/sync`、`/characters/{id}/generate|confirm|replace-primary`

---

### 4.3 分镜与画面

**做什么**：剧本 → 分镜行（`Shot`）；每镜生成多张候选图，用户挑选/确认/驳回；只改选中的镜头，未选中的保持不动。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| `shot_json` 结构化存储 | 台词、旁白、提示词、镜头运动、构图都在里面，前端表格可编辑 |
| 候选图与版本指纹 `shot_fingerprint()` | 只有内容真的变了才升版本（FR-014 不得修改未选中分镜） |
| FR-023 引用完整性 | 分镜引用了未建档/未确认参考图的角色 → 提交前就 409，点名镜号与角色 |
| 参考图注入 | 把角色主参考图随请求传给图像供应商，锁定人物长相 |
| Mock 图像供应商（Pillow） | 离线也能生成真实 PNG，跑通闭环与测试 |

**接口**：`GET /episodes/{id}/shots`、`PATCH /shots/{id}`、`POST /shots/generate-images|select|confirm|reject|restore-candidate`

---

### 4.4 视频生成

**做什么**：确认静态图 → 预估视频成本 → 用户确认 → 逐镜图生视频 → 逐镜确认/跳过/重试。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 两段式生成 | 先图后视频，避免「图不满意还花钱生成视频」 |
| 成本预估 → 门控 → 实扣 | 预估与提交共用同一套参数，预扣与实际结算对账 |
| 视频参数（`video_params`） | 时长、运动强度、镜头运动；越界值自动夹取而不是整条失败 |
| 供应商：Grok Video / Seedance 2 / 可灵 / 方舟 / Mock | 统一 `VideoRequest`，异步任务轮询 |
| 图生视频首帧 | 本地首帧先 `POST /v1/uploads/images` 换公网 URL 再提交（网关不收 base64/相对路径）；上传失败即报错，**不**偷偷退化成文生视频 |
| 「跳过本镜视频」 | 没生成的镜头在合成时用静态图 + Ken Burns 兜底，不阻断交付 |

**接口**：`POST /episodes/{id}/video/estimate|generate`、`POST /shots/{id}/video/confirm|skip|retry`

---

### 4.5 配音与字幕

**做什么**：为每个角色绑音色与语速 → 逐句 TTS → 生成/编辑字幕（SRT/VTT）→ 可加 BGM。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| TTS 适配（Qwen / MiniMax / OpenAI / Mock） | 统一 `SpeechRequest`；未配置时自动回退 Mock（FFmpeg 生成真实 MP3） |
| 音色 + 语速三处留档 | 角色 `voice_speed`、`AudioTrack.speed`、素材 `metadata.speed`，改音色/语速会把旧配音标 `stale` |
| 提交前整体拒绝 | 有台词未绑音色 → 409 `MISSING_VOICE`，点名角色与镜号，不静默跳过 |
| **音色指令前缀** | 通义 `qwen-audio-…-tts-next` 不认 `voice` 参数，改用「用低沉浑厚的成年男声朗读：」控制音色（不会被念出来） |
| 字幕双来源 | 有 TTS 用音频时间轴；没有 TTS 退回分镜台词按镜头时长均分估算 |
| 字幕编辑校验 | 改一条要用「新值 + 另一端原值」重算整条时间轴，倒置/负数直接 422 且不改库 |
| 手动配音 / 跳过配音 | `AudioTrack.source = tts / manual / skipped`，区分「没做」和「有意跳过」 |

**接口**：`POST /episodes/{id}/tts/estimate|generate|manual|skip`、`GET/POST /episodes/{id}/subtitles`、`GET /voices/{id}/preview`

---

### 4.6 合成与导出

**做什么**：把视频片段 + 台词音频 + BGM + 字幕合成预览/成片；打包成素材包 ZIP。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 单条 FFmpeg 命令 | 拼接（concat/xfade）+ 混音（amix + anullsrc 底座）+ 字幕（drawtext）一次完成 |
| filtergraph 转义 | 中文字幕全角化、`fontfile` 路径转义、`enable=between(t\,a\,b)` 单反斜杠 —— 这是最容易踩的坑 |
| 预览 vs 成片 | `-preset veryfast -crf 30` vs `-preset medium -crf 21` |
| AIGC 标识 | 成片强制烧录标识，不可关闭 |
| MP4 元数据 | `-movflags +use_metadata_tags` 才能写入非标准键 |

**接口**：`POST /episodes/{id}/render/preview|render/export|export/package`、`GET /exports/{id}/download`

**素材包结构**：

```
manifest.json   素材清单（sha256 / 尺寸 / 生成参数 / 安全检查结果）
script.json     剧本（含版本）
rights.json     权利与生成信息声明（AIGC 标识）
subtitles/      episode.srt / episode.vtt
images/ videos/ audio/ exports/
README.txt
```

### 4.7 工作流与人工门控

**做什么**：把 8 个智能体串成一条 21 节点流水线，在关键节点停下等人确认。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| LangGraph `interrupt()` | 门控节点暂停图执行，状态写入 checkpoint |
| `langgraph-checkpoint-sqlite` | 断点续跑，`POST /workflow/resume` 带 `checkpoint_id` 恢复 |
| 门控节点「`interrupt()` 前无副作用」 | 恢复时节点体会重放，校验必须放在 `interrupt()` 之后 |
| 降级状态机 `workflow/fallback.py` | `ENABLE_LANGGRAPH=false` 时用等价实现排查问题 |
| **启动即复用已有剧本** | 用户在故事页生成/手改过剧本，点「启动工作流」不会重新调模型（不重复扣费、不覆盖手改） |

**接口**：`POST /episodes/{id}/workflow/start|resume|retry|rollback`、`GET /workflow`、`GET /workflow/graph`

---

### 4.8 任务中心（可靠性）

**做什么**：所有耗时操作（出图 / 出视频 / TTS / 渲染）都是任务，可追踪、可重试、可取消、不重复计费。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 数据库租约队列 | `UPDATE … WHERE status IN (…)` 条件更新领取，进程崩溃后租约过期自动回收；不引入 Redis 也能跑 |
| 内嵌 / 独立 worker | 开发单进程即可；`docker compose --profile workers` 可横向扩容 |
| 幂等键（含 5 秒时间桶） | 连点生成按钮命中同一任务；窗口外算新任务 |
| 自动重试 | 可重试错误 → 同一条任务置 `RETRYING`、次数 +1、退避后再跑，配额预留跨尝试保持 |
| 手动重试 / 取消 / 过期 | `#retry{n}` 新任务 + `parent_job_id`；取消释放配额；长期未完成置 `EXPIRED` |

**接口**：`GET /jobs`、`GET /jobs/{id}`、`POST /jobs/{id}/retry|cancel`

---

### 4.9 成本与配额

**做什么**：每次调用先预估、再预留、成功后按实际结算，失败释放；工作区有总配额。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 三条流水 `RESERVE / SETTLE / RELEASE` | 全部整数分；`used = ΣSETTLE`、`reserved = ΣRESERVE + ΣRELEASE` |
| 价格表 `PriceBook` | 按供应商 / 模型 / 计费单位（call、1k_chars、秒）配置单价 |
| 成本回传链路 | 智能体必须把 `cost_cents` 一路 return 给执行器，否则静默按 0 记账 |
| 预估接口 | 视频、配音、剧本都有 estimate，前端可先展示再提交 |

**接口**：`GET /quota`、`PUT /quota`、`GET /cost/summary|cost/ledger`、`GET /settings/pricing`

---

### 4.10 安全与合规

**做什么**：输入/输出内容检查、风险汇总、素材权利声明、违规申诉、审计与备份。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 安全检查（输入 / 输出） | 命中风险直接阻断，并留下可解释的原因 |
| 申诉必须人工 | 提交只写 `PENDING`，管理员 approve 才放行；同一目标只允许一条待审 |
| 闸门两侧都生效 | 「确认」（`/workflow/resume`）与「导出」（`render/*`、`export/package`）都要检查，只在一边加等于没加 |
| AIGC 标识 + `rights.json` | 成片与素材包都带，满足平台合规要求 |
| 审计日志 + 每日备份 | 删除 / 导出 / 配额调整 / 供应商变更留痕；备份保留 7 份 |
| 上传限制 | 工作区容量配额与类型白名单 |

**接口**：`GET /episodes/{id}/safety`、`POST /episodes/{id}/appeals`、`GET /audit-logs`、`GET/POST /backups`

---

### 4.11 实时进度（SSE）

**做什么**：任务创建、进度、成功/失败、门控等待等状态实时推给前端，断线可续。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| 事件落库 `event_log` | 自增 id 作为游标，多进程/多实例天然对齐 |
| SSE + `Last-Event-ID` | 断线重连从游标之后回放；基于 `sse-starlette` |
| 前端轮询兜底 | SSE 不可用时退回 `GET /jobs/{id}` 轮询，进度不丢 |

**接口**：`GET /episodes/{id}/events`

---

### 4.12 前端工作台

**做什么**：项目 → 剧集 → 六个阶段（故事与剧本 / 角色与画风 / 分镜画面 / 视频 / 音频字幕 / 合成导出）+ 任务中心 + 成本 + 设置。

**技术要点**

| 技术 | 用途 |
| --- | --- |
| Vue 3 `<script setup>` + TypeScript | 组合式 API，类型贯通到接口层 |
| Pinia | `project` / `episode`（含 workflow、job 快照、SSE）/ `jobs` / `config` / `toast` |
| Vue Router | 嵌套路由按阶段切分，门控卡片直接跳对应阶段 |
| 统一错误处理 | 解析 `{"error": {code, message, details, retryable, trace_id}}`，`retryable` 时给重试按钮 |
| limits 不写死 | 候选数、时长上下限、画幅、导出预设全部来自 `GET /config/limits` |
| Vite + vitest + jsdom | 秒级热更新；组件与逻辑单测 |

## 5. 系统架构

```
┌──────────────┐   REST / SSE   ┌──────────────────────────────────┐
│ Vue 3 工作台  │ ─────────────► │ FastAPI  /api/v1/**（143 个接口） │
└──────────────┘ ◄───────────── └───────────┬──────────────────────┘
                                            │
        ┌───────────────────┬───────────────┼───────────────────┐
        ▼                   ▼               ▼                   ▼
┌───────────────┐   ┌───────────────┐ ┌──────────────┐ ┌───────────────┐
│ 工作流引擎     │   │ 任务队列       │ │ 服务层        │ │ 供应商注册表   │
│ LangGraph     │   │ 租约队列+线程池 │ │ 事件/存储/成本│ │ Mock/DeepSeek │
│ 21 节点 6 门控 │   │ 内嵌/独立 worker│ │ 渲染/安全/版本│ │ Gemini/Grok/  │
└───────┬───────┘   └───────┬───────┘ └──────┬───────┘ │ 可灵/通义     │
        └───────────┬───────┴────────────────┘         └───────┬───────┘
                    ▼                                          │
            ┌───────────────┐                                  │
            │ 8 个智能体     │◄─────────────────────────────────┘
            └───────┬───────┘
                    ▼
        ┌────────────────────────────────┐
        │ SQLite + 本地存储 + FFmpeg      │
        │ （可切 PostgreSQL / S3 / Redis）│
        └────────────────────────────────┘
```

**两条执行路径、同一套处理器**：工作流节点内联执行（`run_job_inline`）与队列执行（worker 领取）最终都走 `executor.run_job()`，所以成本结算、状态流转、事件发布行为完全一致。

## 9. 运行与部署

**本地开发**（零中间件）

```bash
cd backend && pip install -r requirements.txt && alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 18437   # 含内嵌 worker

cd frontend && npm install && npm run dev                         # http://127.0.0.1:15731
```

**Docker Compose**

```bash
docker compose up -d --build                 # api + web（Nginx 反代 /api）
docker compose --profile workers up -d       # 独立 worker（横向扩容）
docker compose --profile infra up -d         # Redis + MinIO
```

**供应商配置**：设置页或 `PUT /api/v1/settings/providers`；密钥服务端加密存储，接口只回 `configured` 与掩码前缀。全部留空则自动回退 Mock，闭环仍可跑通。
