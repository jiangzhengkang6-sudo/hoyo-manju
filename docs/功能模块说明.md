# hoyomanju 核心功能模块说明

> 这份文档回答一个问题：**这套系统由哪些功能模块组成，每个模块负责什么，代码在哪，做到什么程度。**
>
> 模块不是按文件夹切的，而是按「用户能用它做什么」切的。每个模块下标了代码位置与数据表，可以直接对照源码；最后一节如实评估各模块的成熟度，避免文档比代码好看。

---

## 0. 全貌

```
┌──────────────────────────────────────────────────────────────┐
│  前端工作台：6 个制作阶段页 + 项目 / 任务 / 成本 / 设置        │
└──────────────────────────────────────────────────────────────┘
                              │
┌──────────────────────────────────────────────────────────────┐
│  内容生产主线（按顺序推进，每步可人工确认）                    │
│                                                              │
│   剧本生成 → 分镜拆解 → 画面确认 → 视频生成 → 配音字幕 → 合成导出 │
└──────────────────────────────────────────────────────────────┘
                              │
┌──────────────────────────────────────────────────────────────┐
│  支撑能力                                                     │
│  角色与画风（一致性）· 任务调度与事件 · 成本与配额 · 供应商接入   │
└──────────────────────────────────────────────────────────────┘
                              │
        安全拦截 / 审计日志 / 版本快照 / 备份恢复（贯穿全局）
```

一句话概括：**这是一条「把文字变成成片」的流水线**，主线上每一步都可能调用外部 AI 供应商、都要花钱、都要人工确认；支撑层解决的是「一致性、可控性、可恢复」。

## 2. M1 项目与剧集管理

**职责**：最外层容器。一个项目对应一部作品，项目下设剧集（每集独立走完整流水线）。

**关键能力**

| 能力 | 说明 |
| --- | --- |
| 项目 CRUD + 软归档 | 归档不删除，列表默认过滤 `ARCHIVED` |
| 剧集 CRUD + 复制 | 复制剧集会连带剧本、分镜（不含生成素材） |
| 概览聚合 | `GET /episodes/{id}/overview` 一次返回阶段、进度、待确认项、成本 |
| 工作台 | `GET /workspace` 跨项目聚合「最近在做的剧集 + 待办门控」 |
| 阶段推进 | `Episode.stage` 单向流转：SCRIPT_REVIEW → … → EXPORTED |

**代码**：`app/api/routes/projects.py`、`app/api/routes/workspace.py`、`app/db/models.py`（`Project` / `Episode`）
**数据表**：`projects`、`episodes`
**前端**：`ProjectsView`、`ProjectDetailView`、`WorkspaceView`

## 3. M2 剧本与分镜创作

**职责**：把一句话故事变成结构化剧本，再拆成可执行的分镜（含台词、音效、画面提示词）。

**关键能力**

- **故事输入与意图分析**：`POST /story/analyze` 先判断这段文字够不够写一集（题材、时长、角色数），避免直接烧钱生成。
- **剧本生成**：`build_script_prompt()` 统一拼提示词，产出 `ShotScript[]`；`STORY_TEXT_MAX_CHARS=2000` 限制输入。
- **结构校验与归一**：LLM 常把 `camera_movement` 写成「推镜头 / pan」，`mode="before"` 校验器做别名归一，认不出回退默认值 —— 单个字段跑偏不会废掉整条剧本。
- **分镜编辑**：`PATCH /shots/{id}` 改动作、台词、时长、转场；改台词会把该镜音频标 stale。
- **局部重生成**：`POST /shots/regenerate` 按镜号只重生成指定镜头，`_parse_shot_patches()` 兼容多种返回格式；分镜版本号只在内容指纹变化时递增。
- **版本快照**：每次剧本变更写 `entity_versions`，可回看历史。

**代码**：`app/agents/story.py`、`app/agents/shot.py`、`app/schemas.py`（`ShotScript`）
**数据表**：`story_documents`、`shots`、`shot_character_refs`、`entity_versions`
**前端**：`EpisodeStoryView`（故事输入 / 剧本预览 / 分镜表 / 局部重生成）

---

## 4. M3 画面生成与确认

**职责**：为每个分镜生成候选图，人工挑一张确认；确认后的图是后续「图生视频」的输入。

**关键能力**

- **成本预估与批量出图**：`POST /shots/estimate-images` 只算选中镜头；`generate-images` 提交异步任务。
- **角色一致性**：拼提示词时注入角色卡的外观特征（`characters_for_shot()`），并限制参考图数量上限。
- **候选图管理**：`candidates` / `select` / `confirm` / `reject` / `restore-candidate`，被驳回的图不会出现在列表里。
- **批量确认**：`confirm-batch` 一次确认多镜，配合前端勾选。
- **素材唯一性**：同名文件不会互相覆盖（存储层独占创建 + 随机后缀），避免「主角立绘被别的角色顶替」。

**代码**：`app/agents/image.py`、`app/services/media.py`
**数据表**：`media_assets`（`kind=image`、`role=shot_image`）
**前端**：`EpisodeShotsView` + `CandidatePicker` + `ShotGrid`

---

## 5. M4 视频生成与确认

**职责**：把确认过的静态图变成短视频（图生视频），或整段文生视频；成片用它而不是静态图。

**关键能力**

- **出片门禁**：必须有 `confirmed_media_id`（已确认画面）才允许提交，缺哪几镜会 409 点名。
- **两段式控成本**：先确认图再出视频，单镜试错成本从「视频价」压到「图价」。
- **参数与估价**：`GET/PUT /video/params` 配分辨率、时长、模型；`POST /video/estimate` 只算选中镜头。
- **逐镜状态机**：`PENDING → CANDIDATES_READY → CONFIRMED / SKIPPED`，支持重试与跳过（跳过则回落静态图）。
- **时长一致性**：生成片段与剧本时长差超 500ms 给警告，合成按剧本时长裁剪。

**代码**：`app/agents/video.py`、`app/providers/custom.py`（图生视频 + 首帧上传）
**数据表**：`shots`（`video_status` / `video_media_id`）、`media_assets`（`role=shot_video`）
**前端**：`EpisodeVideoView`

---

## 6. M5 配音与音频

**职责**：台词逐句合成语音，另加一条氛围音 / BGM 轨；三者分层混音，互不干扰。

**关键能力**

- **逐句 TTS**：按角色绑定的音色与语速合成，每句一条 `audio_tracks`（带 `line_index` 对位，中间某句失败不会整体错位）。
- **音色与语速**：`POST /characters/{id}/voice` 绑定；供应商不认 speed，本地 `atempo` 变速保持音高。
- **手工上传 / 跳过**：可以给某一句换自己录的音频，或明确标记「这句不配音」（与「还没生成」区分）。
- **氛围音 / BGM**：`bgm/suggest` 按镜头内容拼描述（场景 + 音效 + 情绪，不调模型）；`bgm/generate` 支持整集 / 单镜 / 多镜区间，生成后裁剪到窗口长度。
- **试听**：`/voices/{id}/preview` 按需合成并缓存。

**代码**：`app/agents/audio.py`、`app/services/audio_fx.py`
**数据表**：`audio_tracks`、`voices`、`media_assets`（`kind=audio`）
**前端**：`EpisodeAudioView`（音色库 / 台词表 / BGM 卡）

---

## 7. M6 字幕

**职责**：依据台词音频的时间轴生成字幕条，允许逐条校正并导出。

**关键能力**

- **两路来源**：优先用已合成的台词音轨（时间最准），没有音频时按镜头时长均分估算 —— 保证配音前也能出字幕。
- **人工校正保护**：`edited=True` 的字幕不会被「重新生成」冲掉，其余照常重建并重排序号。
- **逐条编辑**：`PATCH /subtitles/{cue_id}` 改文本或时间，按「新值 + 另一端原值」重算整轴再校验，倒置时间轴会被 422 拒绝。
- **导出**：SRT / VTT。

**代码**：`app/agents/edit.py`（`generate_subtitles` / `format_timestamp` / `ass_subtitles`）
**数据表**：`subtitle_cues`
**前端**：`EpisodeAudioView` 下半部分

---

## 8. M7 时间线合成与导出

**职责**：把镜头、音轨、字幕拼成一条时间线，用 FFmpeg 渲染成片。

**关键能力**

- **时间线构建**：`build_timeline()` 按镜号顺序排布，处理转场重叠、音轨基线、字幕偏移；支持 `only_ready=True` 只合成已就绪镜头（部分预览）。
- **合成前校验**：`validate_timeline()` 给出可定位到镜号的错误/警告（缺画面、缺音频、音频过期、素材比例不符、转场超限、BGM 未声明权利……）。
- **三种产物**：低码率预览 MP4、正式导出 MP4（按预设）、素材包 ZIP。
- **渲染细节**：多镜头拼接 + `xfade` 转场、静态图 `zoompan` 转片段、`amix` 多轨混音、`drawtext` 字幕、AIGC 标识烧录。
- **导出闸门**：有未解决的内容拦截时禁止导出；正式导出会记录时间线版本。

**代码**：`app/services/render.py`、`app/api/routes/exports.py`、`app/agents/edit.py`
**数据表**：`exports`、`entity_versions`（时间线快照）
**前端**：`EpisodeRenderView`（时间线列表 / 门控 / 预览播放器 / 导出记录）

## 9. M8 角色与画风资产

**职责**：保证「同一个角色在不同镜头长得一样」，并为整部作品统一画风。

**关键能力**

- **角色卡**：姓名、外貌、服装、性格、音色；`spec_json` 里手改过的字段有 `_user_edited` 保护，自动同步不覆盖。
- **按剧集隔离**：`character_assets.episode_id`（空表示项目级公共），同名角色跨集各存一张，不会互相覆盖。
- **设定图生成与确认**：`spec` / `front` / `half` / `expression` 四类；确认一张作为主形象（`replace-primary`）。
- **画风样式**：`style_assets` 定义色板与风格提示词，`apply` 可批量作用到分镜。
- **自动同步**：剧本生成后立刻从剧本里抽取角色建卡，角色 Agent 节点再幂等对齐一次。

**代码**：`app/agents/character.py`、`app/api/routes/projects.py`（角色/样式段）
**数据表**：`character_assets`、`style_assets`、`shot_character_refs`
**前端**：`EpisodeCharactersView`、`ProjectAssetsView`、`WorkspaceAssetsView`

## 10. M9 任务调度与实时反馈

**职责**：所有耗时操作都异步化，前端能看进度、能取消、能重试；整条流水线还能断点续跑。

**关键能力**

- **11 类异步任务**：剧本生成、剧本重生成、角色素材、画面、视频、台词 TTS、氛围音、字幕、预览、导出、素材包。
- **队列语义**：条件 UPDATE 抢租约、心跳续租、指数退避重试（5/10/20 秒，上限 60）、幂等键（带时间桶）。
- **协作式取消**：批处理循环逐镜探测 `cancel_probe`，已完成的产物保留，只停后续。
- **SSE 实时推送**：任务状态、门控待确认、素材创建；`last_event_id` 断线重连补发。
- **工作流编排**：21 个节点、6 道人工门控，LangGraph checkpoint 持久化，支持中断 / 恢复 / 节点重试 / 回滚。

**代码**：`app/services/jobs.py`、`app/services/executor.py`、`app/services/events.py`、`app/workflow/*`
**数据表**：`jobs`、`workflow_runs`、`workflow_node_logs`、`event_log`
**前端**：`JobsView`、全局任务条（`JobInline` / `JobBadge` / `NodeProgress`）、`GateCard`

## 11. M10 成本与配额

**职责**：每一次 AI 调用都要能预估、能扣费、能追溯，且不能重复扣。

**关键能力**

- **三段式账本**：`RESERVE`（建任务时预留）→ `SETTLE`（成功后按实际结算）→ `RELEASE`（释放差额或失败全额退）。
- **幂等**：同一个 job 结算只记一次；预留按台账口径 `outstanding_reserved()` 计算，避免「负预留」。
- **按实际用量结算**：视频按秒、TTS 按千字、图片按张；裁剪不退税（供应商确实生成了那么长）。
- **配额闸门**：余额不足时在**建任务之前**就阻断，而不是跑完才发现扣不动。
- **多维汇总**：`/cost/ledger`、`/cost/summary`、按项目 / 按剧集。

**代码**：`app/services/cost.py`、`app/services/pricing`（`PRICE_TABLE`）、`app/api/routes/admin.py` 前段
**数据表**：`cost_ledgers`、`price_book`
**前端**：`CostView`、`QuotaMeter`

## 12. M11 供应商接入与降级

**职责**：把 8 家 AI 供应商的差异抹平，并在某家挂掉时不影响整体可用性。

**关键能力**

- **统一协议**：`ProviderCapabilities`（能力、单价、时长范围、预估延迟）+ `ProviderResult`（产物、用量、费用）；文本 / 图像 / 视频 / 语音四类。
- **三种接口形态**：OpenAI 兼容（DeepSeek）、通义 MaaS（TTS/Audiogen）、异步任务网关（Gemini 图 / Seedance 视频）。
- **配置与切换**：`/settings/providers` 存密钥（Fernet 加密）、模型、基址；换供应商只改配置。
- **熔断与恢复**：某类依赖连续失败超阈值即暂停该类新任务（503 + 原因），成功一次自愈；被拦截需人工申诉批准。
- **Mock 兜底**：密钥缺失自动回退 Mock，零预算也能跑通全链路（CI / 演示）。

**代码**：`app/providers/*`、`app/services/registry.py`、`app/services/degraded.py`
**数据表**：`provider_settings`、`provider_calls`
**前端**：`SettingsView`

## 13. M12 安全、审计与版本

**职责**：拦住不该出的内容，留下该留的痕。

**关键能力**

- **输入检查**：提交故事 / 提示词前做敏感内容检查，命中即拒绝并给出原因。
- **输出检查**：素材生成后标记 `safety_status`，被拦截（BLOCKED）的素材禁止确认与导出。
- **申诉**：`POST /episodes/{id}/appeals` 提交，人工复核 `resolve(APPROVED)` 才放行，同一目标只允许一条待审。
- **审计**：门控决策、导出、供应商配置变更全部写 `audit_logs`。
- **版本与备份**：`entity_versions` 存剧本 / 分镜 / 时间线快照；启动时自动备份数据库，保留最近 7 份，支持恢复。

**代码**：`app/agents/safety.py`、`app/services/audit.py`、`app/services/versions.py`、`app/services/backup.py`
**数据表**：`approvals`、`audit_logs`、`entity_versions`、`safety_appeals`
**前端**：分散在剧本页 / 预览页 / 设置页

## 14. 模块之间的依赖

```
项目与剧集
   └─ 剧本与分镜 ──┬─ 角色与画风（提供一致性提示词）
                   ├─ 画面生成 ── 视频生成 ──┐
                   └─ 配音与音频 ── 字幕 ─────┤
                                              └─ 时间线合成与导出
                                                        │
全部模块 ── 任务调度（异步执行）· 成本与配额（每次调用记账）· 供应商接入（真正干活）
                                                        │
                                            安全拦截 / 审计 / 版本 / 备份
```

几条隐含的强依赖，改代码时容易踩：

1. **画面 → 视频**：视频任务必须有 `confirmed_media_id`，没有就 409。
2. **台词 → 字幕**：字幕时间轴依赖台词音轨；改台词会把音频标 stale，字幕也要重生成。
3. **镜头时长 → 混音 → 渲染**：改时长会让转场、字幕、音轨全部错位，所以时间线要重新校验。
4. **成本 → 一切**：任何生成动作都会先预留；任务失败必须释放，否则配额会「漏气」。

## 15. 成熟度评估（如实）

| 模块 | 完成度 | 说明 |
| --- | --- | --- |
| M2 剧本 / M3 画面 / M4 视频 | ★★★★☆ | 主链路完整，有真实调用记录与回归用例；缺「多候选自动评分」这类智能选择 |
| M5 音频 / M6 字幕 | ★★★★☆ | 逐句 TTS、对位、变速、字幕校正都可用；音乐风格控制仍依赖提示词 |
| M7 合成导出 | ★★★★☆ | FFmpeg 链路完整（转场/混音/字幕/水印），部分预览刚补上；缺自动调色 / 音效库 |
| M9 任务与编排 | ★★★★☆ | 11 类任务、21 节点、6 门控、断点续跑都在；缺多机分布式调度 |
| M10 成本 | ★★★★☆ | 账本、幂等、按量结算都有；单价是人工维护的表，没接供应商真实账单 |
| M8 角色与画风 | ★★★☆☆ | 角色卡与一致性提示词可用；画风只到「提示词 + 色板」，没有 LoRA 级别的风格固化 |
| M1 项目与剧集 | ★★★☆☆ | CRUD、归档、概览齐全；工作台聚合较简单 |
| M11 供应商 | ★★★☆☆ | 8 家可插拔、有熔断；但「能力探测」是静态声明，不是实时探测 |
| M12 安全 | ★★☆☆☆ | 有拦截与申诉流程，但检测规则偏基础（关键词 + 素材标记），没有多模态安全模型 |
| M6 前端工程 | ★★★☆☆ | 类型与测试齐；缺 i18n、无障碍（a11y）系统化打磨 |

**结论**：主线（剧本 → 分镜 → 画面 → 视频 → 音频 → 合成）是真正跑通的；支撑层里「任务、成本、供应商」做得比「安全、画风、工作台」更实。如果继续演进，优先级建议是：安全检测能力 > 画风一致性（LoRA）> 工作台聚合 > i18n。
